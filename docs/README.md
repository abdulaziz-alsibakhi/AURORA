# AURORA Documentation

This directory is the technical memory of the project. It should make AURORA understandable to a new team member without requiring them to reconstruct decisions from chat history.

| Directory | Purpose |
|---|---|
| `system-design/` | Architecture, interfaces, requirements and control flow |
| `reservoir-knowledge/` | Minimum domain knowledge and terminology needed by the team |
| `validation/` | Experimental scope, operating envelope, rules and evidence |
| `simulation/` | OPM Flow / EGG reference-environment documentation |
| `ai-controller/` | Learned-controller design and experiment assumptions |
| `safety-controller/` | Reduced-order model, QP and model-mismatch design |
| `data-and-logging/` | Schemas, telemetry, provenance and dataset usage |
| `robustness/` | Fault models, abnormal inputs and resilience testing |
| `experiments/` | Evaluation methodology, baselines and metrics |
| `demo/` | Dashboard and presentation-facing system behavior |
| `reports/` | Capstone deliverable planning and traceability |
| `meetings/` | Durable decisions/action items from important meetings |
| `decisions/` | Architecture Decision Records (ADRs) |
| `team/` | Ownership and knowledge-sharing expectations |

Documentation should evolve alongside implementation. Unknown facts should be marked explicitly rather than filled with guesses.
