# System Design

This workstream defines what AURORA is as a software system. It owns the system context, component boundaries, interfaces, control loop, functional/non-functional requirements, use cases, and major design alternatives.

Before the architecture is considered frozen, the team should define the observation vector, action vector, control interval, objective/reward, constraints, simulator state used for evaluation, controller-visible information, safety-controller inputs/outputs, telemetry schema, and failure behavior.

Diagrams belong in `diagrams/`. Important architectural choices should also receive an ADR under `docs/decisions/`.
