# Architecture and Project Decision Records

This directory preserves the rationale for consequential AURORA decisions.

An ADR is appropriate when a decision materially affects architecture, interfaces,
project scope, experimental methodology, safety behaviour, validation, or another
choice that future contributors may reasonably ask "why did we do this?"

ADRs preserve decision history. Current specifications remain authoritative for the
current design.

## Lifecycle

Recommended status values:

- Proposed
- Accepted
- Superseded
- Rejected

Do not delete an accepted ADR because the project later changes direction. Mark it
Superseded and link the newer decision.

## Naming

Use a stable sequence and descriptive title, for example:

    ADR-0001-example-decision.md

Do not allocate an ADR number until there is an actual consequential decision to
record.
