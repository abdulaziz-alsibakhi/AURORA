# Project Principles

1. **Evidence over assertion.** Claims should point to tests, experiments, sources, or other concrete evidence.
2. **Reproducibility.** Important experiments need identifiable configurations, versions, seeds where relevant, and result provenance.
3. **Explicit assumptions.** Domain assumptions belong in documentation, not hidden inside implementation.
4. **Respect domain boundaries.** Reservoir physics and constraints should come from defensible sources or qualified review rather than invention by the software team.
5. **Match safety claims to evidence.** Enforcing encoded constraints in a modeled environment is not the same as proving real-field safety.
6. **Higher fidelity is not ground truth.** Numerical reference simulation remains simulation.
7. **No single-person black boxes.** Major subsystems need documentation and backup understanding.
8. **Traceability.** Requirements/questions should connect to issues, implementation, verification, evidence, and reporting.
9. **Prefer understandable names.** Use descriptive English rather than unnecessary internal codes.
10. **GitHub is the engineering source of truth.** Repository for engineering artifacts, Issues for work, Projects for status, external storage for large data/artifacts, Discord for conversation.
